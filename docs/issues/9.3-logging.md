## Ringkasan
`report_mauto_service.py` menulis 1 log `INFO` per request berisi NIK lengkap. File log memakai `RotatingFileHandler` dengan nama tanggal saat service start.

## Bukti (before, 2026-11-03)
- `logs/detailed_2026-10-01.log`: 1.162 dari 1.180 baris INFO memuat NIK; file ini masih ditulis pada 2026-11-03 (±1 bulan dalam satu file)
- Contoh (disamarkan): `INFO - report_mauto nik=3201********0002 apply_date=2025-09-29 rows=10`
- Allure **TC-24** gagal (NIK di log INFO), **TC-25** gagal (`RotatingFileHandler`, bukan rotasi harian)
- Detail: `docs/load-test/2026-11-03/BASELINE-ISSUES.md` §9.3

## Dampak
Data pribadi (NIK) tersimpan di file log; log membesar cepat saat beban tinggi; rotasi per hari tidak terjadi.

## Rencana perbaikan
`docs/implementation-fixing-plan.md` P3: hapus NIK / turunkan ke DEBUG, `TimedRotatingFileHandler(when="midnight")`, `LOG_LEVEL` dari env.

## Perbaikan (2026-11-03)
Log per request DEBUG tanpa NIK, `MaskingFormatter` (NIK & traceback), `hide_parameters=True`,
rotasi harian, env `LOG_LEVEL`/`LOG_DIR`/`LOG_RETENTION_DAYS`. Detail: `docs/load-test/2026-11-03/FIX-9.3.md`.

## Definisi selesai
- [x] TC-24 & TC-25 lulus, tag `@known_issue` dihapus; TC-28 (NIK di error/traceback) ditambahkan
- [x] Bagian After di `BASELINE-ISSUES.md` diisi
- [ ] File log lama yang berisi NIK diarsipkan/dihapus (koordinasi security)
